Tester: Claude (browser automation, signed-in Chrome)
Scope: marketing site, tutor app on Solo trial, file feature, parent portal, common edge cases.

## Phase 1 — Marketing pages (cold visitor)

### P0-1.1 — Stripe "Skip the trial — pay now" links go to TEST mode on the live site
- **Page**: `https://crestio.ai/` (pricing section, both monthly and annual)
- **What I saw**: The Solo and Team "Skip the trial — pay now →" anchors point to:
  - Solo: `https://buy.stripe.com/test_28E8wRgoDeqrdP88MS0ZW01`
  - Team: `https://buy.stripe.com/test_00w5kFa0faab8uO1kq0ZW03`
- **Repro**: View source on the homepage pricing cards (or click either "Skip the trial" link — destination is `buy.stripe.com/test_…`).
- **Fix**: Replace with the live `buy.stripe.com/…` URLs. Confirms the known issue. There is no Growth equivalent (Growth uses a `mailto:` "Contact us →"), so only two URLs to swap.

### P1-1.1 — Logged-in user sees the cold-visitor nav on every public page
- **Page**: `/`, `/contact`, `/privacy`, `/terms`, `/auth/forgot-password`
- **What I saw**: While signed in as the tutor, the homepage header still shows "Pricing · Sign in · Start free trial". The page IS authenticated — network shows 10+ `/api/billing/status` GETs and many `organization_members` queries to Supabase for the signed-in user — but the header doesn't reflect it. A logged-in user clicking "Sign in" gets bounced into `/app`, and clicking "Start free trial" goes to a sign-up form that doesn't make sense for them.
- **Repro**: Sign in, then navigate to `https://crestio.ai/`.
- **Fix**: Read auth state in the marketing nav and render "Go to dashboard" when authenticated, hide "Sign in"/"Start free trial". As a side benefit this would let you stop firing all those `/api/billing/status` calls on marketing pages (see P1-1.2).

### P1-1.2 — Massive over-fetching on every page load
- **Page**: every page (worst on `/`)
- **What I saw**: One load of `https://crestio.ai/` triggered:
  - 10+ `GET /api/billing/status`
  - 12+ `select=organization_id,role` from `organization_members`
  - 7+ `select=*` from `organizations`
  - 24 separate locale JSON files preloaded (`assistant.json`, `auth.json`, `common.json`, `dashboard.json`, `emails.json`, `errors.json`, `files.json`, `households.json`, `invoices.json`, `legal.json`, `lesson_plans.json`, `messages.json`, `notifications.json`, `onboarding.json`, `owner.json`, `parent.json`, `payouts.json`, `sessions.json`, `settings.json`, `students.json`, `tutors.json`, `welcome.json`) on a marketing page that needs none of them.
- **Repro**: `read_network_requests` for `https://crestio.ai/` after a fresh load.
- **Fix root cause**: This looks like context providers (auth + i18n) being mounted at `_app` level firing on every render. Lazy-load locales by route namespace; debounce or cache `/api/billing/status`; don't query Supabase from a public marketing page when you can read the cookie session once.

### P1-1.3 — Four marketing screenshots return 404; page falls back to "SCREENSHOT COMING SOON"
- **Page**: `/` (How Crestio works section)
- **What I saw**: The homepage embeds 4 placeholder slots with the literal text "SCREENSHOT COMING SOON". HEAD checks confirm:
  - `/marketing/screenshot-1.png` → 404
  - `/marketing/screenshot-2.png` → 404
  - `/marketing/screenshot-3.png` → 404
  - `/marketing/screenshot-4.png` → 404
- **Repro**: `curl -I https://crestio.ai/marketing/screenshot-1.png`.
- **Fix**: Either ship the assets (you have the i18n + viewer already shipped, you can self-screenshot the dashboard, log session form, AI polish, and parent portal), or remove the 4 boxes and tighten the section so it doesn't read as half-built.

### P1-1.4 — Auth pages have generic `<title>`; marketing pages have proper ones
- **Pages**: `/auth/signin`, `/auth/signup`, `/auth/forgot-password` all have `<title>Crestio — run your tutoring business</title>` (the default app title). `/contact`, `/privacy`, `/terms` have proper per-page titles ("Contact · Crestio", etc.).
- **Repro**: Open each page, look at browser tab.
- **Fix**: Add `<Head><title>Sign in · Crestio</title>` etc. on the auth pages — needed for SEO of those landing pages and for the user reading their tab strip.

### P1-1.5 — All form inputs lack `name` and `autocomplete` attributes
- **Pages**: `/auth/signin`, `/auth/signup`, `/auth/forgot-password`, `/contact`, plus `/parent/accept` (Phase 4) and `/parent/signin`.
- **What I saw** (signup as example):
  ```html
  <input type="email" required autofocus class="input" value="">
  <input type="password" required minLength="8" class="input" value="">
  ```
  No `name`, no `autocomplete`, no `id` or `<label for=>`.
- **Why it matters**: 1Password / iCloud Keychain / Chrome can't reliably autofill or save the new account. Screen readers can't associate the visible "EMAIL" / "PASSWORD" headings with the inputs (the headings sit above as separate text, not in `<label>`). And on `/parent/accept` Chrome's autofill mis-fills the "Your name" field with my email (see P1-4.2).
- **Fix**: `name="email" autocomplete="email"`, `name="new-password" autocomplete="new-password"` (or `current-password` on signin), `name="name" autocomplete="off"` on the parent name field. Wrap each input in `<label>` or use `htmlFor`.

### P2-1.1 — Footer copy inconsistency

- `/contact` footer: "crestio · Sydney · 2026"
- Pick one and use it everywhere.

### P2-1.2 — Two different support emails

## Phase 3 — File feature

### P1-3.1 — No watermark visible on PDF view (tutor or parent)
- **Page**: `/files/3b255baa-…` (the test 212112.pdf), accessed both as the tutor and as the invited parent.
- **What I saw**: The viewer renders the PDF cleanly. DOM scan finds zero text containing the org name (`leninlcj+crestiotest`), no SVG `<text>`, no fixed/absolute overlay element with text. Only on-page texts are: the `<title>`, the inline "crestio" link top-left, and a hidden `<p>` with the app title. Nine `<canvas>` elements (the pdf.js pages) — none have a watermark drawn into them either, judging by the rendered screenshot.
- **Maybe by design**: The /app/files Team upgrade prompt says "Upgrade to Team to enable the org library, **watermarking**, and search." That suggests Solo intentionally has no watermark. If so, the audit prompt's expectation ("watermark uses org name" applies to Solo) was wrong.
- **If by design**: nothing to fix in code, but two things to fix in messaging: (a) the recent commit message `files: per-file print toggle + watermark uses org name` reads as if watermarking ships in this commit for everyone; (b) there's no in-product hint to a Solo tutor that "watermarking is a Team feature" when they look at a file viewer.
- **If a regression**: investigate why the `org_name` watermark isn't being injected into the pdf.js render or as an overlay div.

### P2-3.1 — "Allow printing" toggle controls save AND print, but only the print word is in the label
- **Page**: per-file row on `/app/students/<id>` Files tab
- **Label**: "Allow printing"
- **Description**: "Let students and parents save or print this file."
- **Behaviour**: Toggling on un-blocks both Cmd+S and Cmd+P. Toggling off blocks both.
- **Fix**: Rename to "Allow save & print" or "Allow download" (or invert: "Block download — save and print disabled").

### P2-3.2 — Audit log records duplicate views within the same session
- **Page**: per-file row · click "viewed N times"
- **What I saw**: Three view entries logged within ~100 seconds of each other (5:34:03 PM, 5:35:43 PM, 5:35:45 PM) when I navigated away and back twice. The 5:35:43 / 5:35:45 pair is two opens 2 seconds apart — should probably be debounced into one event per session window.
- **Fix**: dedupe per `(viewer_id, file_id)` within a 5-minute window, or insert a `view_started_at` and only count distinct sessions.

### P2-3.3 — File viewer has no toolbar
- No filename shown, no breadcrumb, no back-to-student link, no download button (when print is allowed). Only "crestio" logo top-left links to /app. A back link or close button would help.

### Confirmed working
- Cmd+S preventDefaulted when print toggle off (tested as tutor and as parent — both correct).
- Cmd+P preventDefaulted when print toggle off (tutor and parent).
- Cmd+S NOT preventDefaulted when print toggle on (browser save dialog would appear — correct behaviour).
- Toggle state persists across navigation.
- Audit log captures viewer email, role ("owner" for me), and timestamp per view.
- `viewed N times` count increments correctly (3 → 6 after I opened the file 3 more times).
- Storage shows 265.2 KB / 5.00 GB on Solo.
- Upload section copy correctly says "PDFs and images. Word, Excel, and PowerPoint coming soon." (matches Office-is-Team-only).

## Phase 4 — Parent portal

### P1-4.1 — Parent invitation email plaintext body has a corrupted character where `=` should be
- **Page**: the email sent by `hello@crestio.ai` to the invited parent
- **What I saw** (plaintext body, exact extract):
  ```
  Accept the invitation here:
  https://crestio.ai/parent/accept?token�bd0e20678ce19d0d1181e5a348731d31d3d4ee58373684c9fbc38b9ede2ee2
  ```
- **DB token** (queried directly from `parent_invitations`): `b5bd0e20678ce19d0d1181e5a348731d31d3d4ee58373684c9fbc38b9ede2ee2`
- **What's happened**: The `=` between `token` and the value, plus the leading `b5` of the hex token, have been replaced by a single Unicode replacement character (`�`). Looks like a UTF-8 → ASCII conversion that ate three bytes and emitted one. Probably the email template uses an em-dash, smart-quote, or non-breaking space adjacent to the token interpolation, and an encoding step downstream mangled it.
- **Impact**: Parents on plaintext-only email clients (or who copy-paste the link) get "Invitation unavailable. Invitation not found." — a dead end for onboarding.
- **Repro**: Invite a parent, view the plaintext part of the resulting email.
- **Fix**: Audit the email template for the parent-invitation email. The HTML version (which most clients render) may have a clickable `<a href>` that's correct — verify, then fix the plaintext branch. Likely culprit: a templating function that's running through a character normalizer on the wrong branch.

### P1-4.2 — `/parent/accept` form: Chrome auto-fills "Your name" with the user's email and password with the user's saved Crestio password
- **Page**: `/parent/accept?token=…`
- **What I saw**: Visiting the accept page with my Chrome session (which has crestio.ai saved credentials) populated the visible "Your name" textbox with `leninlcj@gmail.com` and the password field with the Crestio password — both purely from Chrome autofill, since the inputs lack `name`/`autocomplete` (see P1-1.5).
- **Worse**: the auto-filled values do **not** propagate into React state, so the "Create parent account" submit button stays disabled even though the form looks filled. A confused parent might click and click and nothing happens.
- **Fix**: Add `autocomplete="off"` (or specifically `autocomplete="name"` / `autocomplete="new-password"`) to the relevant inputs and pair with proper `<label>`. The accept form is the parent's first interaction with your product — it has to feel right.

### P1-4.3 — After parent account creation, redirect lands on `/parent/signin?just_created=1` but no success banner is rendered
- **Page**: `/parent/signin?just_created=1`
- **What I saw**: Successful submit of the accept form sent me to the parent sign-in page. The URL has `?just_created=1` (so the intent to display a success message clearly exists) but the page renders the same empty Sign in form with zero confirmation text. A new parent would have no signal that their account was actually created.
- **Fix**: Render a success banner above the form when `just_created=1` is present: "Your parent account is ready — sign in to view <Student>'s sessions."

### P1-4.4 — Parent sign-out lands on the **tutor** sign-in page with `reason=session_expired`
- **Page**: post-sign-out destination after clicking "Sign out" in `/parent/dashboard`
- **What I saw**: Lands at `https://crestio.ai/auth/signin?reason=session_expired`. Two issues:
  1. Wrong destination — parents should go to `/parent/signin`, not the tutor sign-in.
  2. Wrong reason — they pressed Sign out, the session didn't expire. The `reason=session_expired` flag is misleading and would also be wrong if the form were to display "Your session expired" text.
- **Fix**: Sign-out from `/parent/*` should redirect to `/parent/signin` with no `reason` param.

### P1-4.5 — Forbidden parent route silently redirects to `/parent/dashboard?error=no_access` with no banner
- **Page**: `/parent/student/<other-student-uuid>` for any student the parent isn't invited to.
- **What I saw**: Redirected to `/parent/dashboard?error=no_access`. The dashboard renders normally — no error toast, no banner. Same issue as P1-4.3: a query param flagging an outcome with no UI to display it.
- **Fix**: Render a dismissible banner on the dashboard when `error=no_access` is present: "You don't have access to that student. If this is a mistake, ask the tutor."

### P2-4.1 — "Sessions this year: 0" while a session is scheduled today
- **Page**: `/parent/dashboard` (At a glance)
- The "Sessions this month" and "Sessions this year" both show 0, while "This week" correctly shows the scheduled session at 6:00 PM. Likely the counters only count completed sessions — which is fine, but the column should say "Completed sessions this month/year" so it's not surprising.

### Confirmed working — parent isolation
- Cannot view another student's profile in this same org (`/parent/student/<thomas-uuid>` → redirects to `/parent/dashboard?error=no_access`).
- Cannot reach `/app` (any tutor route) — silently redirects to `/parent/dashboard`.
- Cannot reach a random nonexistent UUID's parent page — same redirect.
- Cmd+S / Cmd+P blocked on the file viewer for the parent (same as for the tutor).

### Confirmed working — parent UX
- Magic link form pre-fills the email (read-only) with helper "From your invitation. Can't be changed here."
- Parent dashboard layout: "Hi <Name>" greeting, "This week" upcoming-session card, "Your children" list, "At a glance" metric cards (Sessions this month / year, Paid, Outstanding).
- Per-student page tabs: Calendar / Sessions / Homework / Invoices / Updates / Files.
- Files tab calls the section "Resources" and lists the PDF with a "View →" link.
- Sign in form correctly catches credentials and lands on `/parent/dashboard`.

## Things I'd recommend doing first

1. **Swap the two Stripe "Skip the trial — pay now" URLs to live mode.** This is the only P0 — it actively blocks revenue.
2. **Fix the parent invitation email plaintext encoding.** Onboarding the very first parent after a tutor signs up is the make-or-break moment — getting "Invitation unavailable" because the plaintext was mangled is a trust-killer.
3. **Add `name` + `autocomplete` to every input.** One small change unblocks password managers across signin / signup / parent accept / parent signin and removes the "Chrome filled my parent name with my email" surprise.
4. **Render banners for the query params you already set** (`?just_created=1`, `?error=no_access`, `?reason=session_expired`). The plumbing's done; just hook up the UI.
5. **Decide whether watermark is a Solo or Team feature, then make the messaging match.** Right now /app/files implies Team-only, but the recent commit message implies it shipped for all.
